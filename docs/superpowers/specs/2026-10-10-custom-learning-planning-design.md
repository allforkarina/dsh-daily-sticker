# 自定义每日学习规划 — 0.2.0 设计

状态：用户已于 2026-10-10 确认方案可行，并要求编写修改实施计划。依据：用户逐项确认：大段自由文本需求；模型生成并保存完整阶段路线；可修改需求重新生成路线；任务完成勾选推进；阶段目标及预计天数提前规划，具体任务每日生成。

## 目标

在现有每日任务备忘录中，允许分别描述算法、LLM、Agent 工程和 AI 探索的学习需求。用户不必自己制定完整准确的规划；宿主模型从自由文本提取目标、路径、偏好及约束，按该类别的每日预算生成完整阶段路线，再每日细化任务。继续使用现有时间预算、完成勾选和本地日期保存。

## 设置

新增“学习需求与路线”区域，每类提供一个大文本框，可粘贴 Markdown 或自由文本，描述想学什么、已有基础、目标、内容倾向、希望避免的内容及可选学习期限。无需填结构化表单。

每类分别保存需求，并提供“生成路线／重新生成路线”。模型生成的路线可以展开查看：整体目标、规划依据或假设、全部阶段、每阶段目标和按每日预算估算的天数、当前阶段。模型生成不要求用户再逐章确认。

保存需求与激活新路线是两个明确动作：编辑需求不会悄悄替换旧路线；生成成功后新路线生效。界面显示需求已经改变但路线尚未更新。每类独立更新，避免修改一个方向时重置其他类别。

角色风格保持独立；现有工程项目、AI 兴趣、预算和内置 LLM 起点保留。没有需求或没有自定义路线时，继续现有默认规划。

清空某类需求并保存时停用该类自定义路线，旧版本仍保留，已有日计划不自动修改。

## 完整路线与每日推进

路线包含完整阶段规划及估算天数，不提前固定所有日期的具体任务。模型可根据需求估算合理学习周期；没有明确期限时说明估算依据，不捏造用户基础。AI 探索按关注领域、体验目标和阅读重点组织阶段，具体资讯在当天检索。

每日生成时提供当前路线、当前阶段、时间预算及相关历史任务，安排一个适合当天时长的小任务。每个自定义任务保存其路线版本和阶段标识。

一个日期、一个类别最多计一次推进。已完成的每日任务增加当前阶段的完成天数；达到该阶段预计天数后，下一次生成进入后续阶段。未完成则继续当前阶段。重新规划或反复勾选不会重复计数，取消勾选后后续生成重新按实际完成记录计算。已保存任务不会因为后来改变完成状态而自动覆写。

勾选只表示完成任务，不等于掌握整个阶段。全部阶段完成后，显示路线已完成；后续任务围绕复习或综合实践，提示可修改需求继续规划，不自动创建新路线。

## 修改方向

用户修改或重新粘贴自由文本，再点击重新生成路线。模型同时获得原路线及已完成任务摘要，以便整理新的目标和后续路线；用户明确声明的基础或已掌握内容优先，不把历史勾选当作知识掌握证明。

新路线使用新版本和独立阶段进度，旧完成记录不机械地套用到新阶段。原路线和历史任务保留，可供查看及生成时参考。当天已完成任务保留；未完成任务通过明确“重新规划未完成项”使用新路线。

## 生成规则

用户需求及已生成的自定义路线优先于内置路线和默认兴趣。当前工程项目仍用于约束工程任务的实际场景；若学习路径与项目无法兼顾，给出适合当前阶段的最小任务，不能假定用户已学完前置内容。

LLM 和 Agent 的内置主题是未自定义时的后备路线，不能要求模型继续遵循与自定义规划矛盾的内置主题。近期计划只提供上下文，已勾选任务不等于掌握整个章节。

算法规划应影响真实题目的选择与练习方向；只能引用已验证的 LeetCode Easy/Medium 题。无法获取符合方向的真实题目时应说明限制，不编造题目或声称已匹配。

AI 探索的自定义规划还用于调整资讯检索方向，避免只改变模型提示词而仍检索旧兴趣。继续核验来源、正文及时间；无可用资料时提供明确的非时效练习，不能伪造近期资讯。缓存随相关规划改变而区分。

复制学习 Prompt 时包含对应类别的角色风格、需求、路线目标、当前阶段及实际任务，使外部学习工具获得同样的上下文。

## 生效与兼容

路线生成成功后用于下一次任务生成。已有今日计划不自动覆写；用户点击“重新规划未完成项”即可应用新路线，已完成任务保留。修改时间预算后每日任务立即按新预算规划，阶段预计天数仍依据生成路线时的预算，界面提示可重新生成路线更新估算。

路线生成必须配置宿主模型。未配置时给明确提示，不伪造解析后的路线。生成失败、超时或输出不合格时保留原路线和已保存需求；生成期间需求或数据发生变化时拒绝提交旧结果，允许重试。

每日模型失败时仍有模板；存在自定义路线时模板显示真实当前阶段及目标，并说明尚未细化，不能退回与自定义路线矛盾的内置主题。不承诺模板能理解任意自由文本。

旧版数据缺少新字段时补充空默认值，保留旧目录、历史计划、角色风格和勾选状态。偏好和路线保存遵循现有原子写入及版本冲突保护。需求输入每类最多 12000 字符，支持换行及 Markdown；合理限制路线结构和请求大小，确保多类中文需求可正常保存。
