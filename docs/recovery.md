# 数据恢复

`store/state.json` 是权威数据，包含偏好、学习需求、路线版本、日期任务和简单完成标记。日期和路线 JSON/Markdown 是派生快照。不要把手工编辑 Markdown 当作修改插件状态。

每次权威写入前保存上一份有效 state 到 `backups/`，保留最近 30 份。插件停用或移除不会删除数据。

## 从 0.1.0 更新

0.2.0 使用 schema 2。第一次打开旧目录时，完整校验旧状态，将原始文件备份到 `backups/state-v1-before-0.2.0-<ID>.json` 后原子升级。旧偏好、任务和完成勾选保留，新增需求及路线默认为空。升级备份单独保留，不参与最近 30 份日常备份轮换。

升级后请使用 0.2.0 或支持 schema 2 的版本。需要回退到 0.1.0 时，先停用并退出新版 Host，保留整个新版目录副本，在单独的恢复目录使用 schema 1 升级备份作为 `store/state.json`，并保留原目录标识文件。不要让 0.1.0 直接打开 schema 2 数据，也不要在新版仍运行时替换权威文件。

当前阶段按每日任务中的路线/阶段标识与完成状态计算。路线重新生成会创建新版本，旧任务、旧路线仍能查看；旧完成天数不会直接计入新路线。

## 重新安装或换目录

重新选原 dataRoot 即可恢复。换到新空目录会建立新学习空间；旧目录保留。旧的规划请求会在配置重载时取消，不把结果写入新目录。

## 恢复备份

1. 在宿主中停用插件并重启，确保没有 Host 写入该目录。
2. 保存一份当前损坏或需要回退的 `store/state.json`。
3. 从 `backups/` 选一份有效文件，复制为 `store/state.json`。
4. 重新启用插件。日期快照会从恢复后的 state 重建。

未来版本的 schema 不受当前版支持时，插件拒绝写入并保留文件。使用匹配版本，或在停用后显式恢复兼容备份。

## 日期文件待同步

如果界面显示「计划已保存，日期文件待同步」，权威记录已经提交。修复目录权限或磁盘问题后，重新打开插件即可重试生成快照，不需要重新调用模型。

## 写入锁

同一目录只允许一个 Host。仍有活动进程时第二个 Host 不会写入。相同机器的已退出进程锁可自动恢复；无法判断归属时保留锁并报错。只在确认所有相关 Host 已退出后处理异常 `.writer.lock`，不要按过期时间强行夺取。
